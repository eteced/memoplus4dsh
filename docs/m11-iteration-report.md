# memoplus4dsh 机制详解与迭代结论

> English: [m11-iteration-report.en.md](m11-iteration-report.en.md)

> 日期：2026-09-05 · 本文回答三个核心问题：抽取怎么做、去重/关联怎么做、检索注入怎么做。
> 迭代过程（7 轮 smoke/mini 的每轮发现）压缩在附录 A；全量复测需用户授权。

## 1. 实体、事件、关系与时间的抽取：时机与方式

### 1.1 时机

**每轮对话结束时**（dsh 事件总线的 `turn/end` 且 reason=completed）触发一次异步抽取，进串行队列（一次一个 LLM 调用，失败按 5s/30s backoff 重试 2 次，再失败跳过并记录）——不阻塞对话。持久化 pending 日志（enqueue 一行、settle 一行 tombstone）：进程崩溃重启后未 settle 的轮次自动补抽，且补抽幂等（见 §2.3 事件去重）。

另外还有两条写入路径：**进度桥**（dsh 的 goal/change、todo/write、schedule/change、plan/mode 内部事件直接投影为记忆事件，不过 LLM）和 **`memory_remember` 工具**（用户明确说"记住…"时模型直写）。

### 1.2 抽取输入的构造

从会话日志重建本轮文本，只收四类：`User:`（真实输入）、`Goal:`（goal 模式轮次提示，长程任务进度的核心上下文）、`Schedule:`（提醒派发）、`Assistant:`（模型回复）。**明确排除**运行时上下文快照、工作区指令、以及本插件自己的注入块（否则记忆自我复制）。超长输入两级防护：20k 字符截头尾，再按 8k 字符分段独立抽取后合并（分段尺寸来自实测：推理模型在 ≥17k 字符密集输入上会无限推理、可见输出为空）。

### 1.3 方式：LLM pipe 九列表格协议

一次 LLM 调用（显式关闭 thinking），输出协议：

```
ENTITY_TYPE|CANONICAL_NAME|ALIASES|PREDICATE|OBJECT|TIME_EXPR|NORMALIZED_FACT|DETAILS|KIND
PERSON|Bob|Bobby|painted|landscape|last year|Bob painted a landscape last year.|_|fact
```

关键规则（均为通用语言规则，无数据集词汇）：

- **指代消解**："we did it"、"那只猫"展开为具体实体——每条事实脱离上下文可读；
- **列表逐行**（"likes A, B, C" → 三行）；静态属性用 `is`；
- **说话人即实体**：陈述/提问的主体是说话人，谓词表达言语行为；
- **TIME_EXPR 逐字复制，禁止模型算日期**——"last Saturday"相对哪个基准是确定的，绝对时间由确定性代码换算（LLM 日期算术不可靠）；
- **不抽指令/规则/任务元叙述**（"answer only from the knowledge pool"这类入图后会与每个查询逐字重合、霸占检索 top-k）；
- **KIND 列**：模型自己判定该行是事实（`fact`）还是言语行为（`speech`）——语义判定而非词表匹配，任何语言成立；
- 事实语言跟随对话语言；已知实体提示（按当前文本相关性过滤、带既有类型、4000 字符硬顶）引导复用规范名。

### 1.4 事件的结构（图的基本单位）

```
事件 = (主体实体集, 客体实体集, 谓词, 自包含事实, 细节,
        timeExpr(原文逐字), eventTime(ISO,可空), 精度(year~second),
        mentionTime(轮次结束时刻,恒非空), 来源(session+turn),
        speechAct?, supersededBy?, embedding?)
```

**双时间锚**：`eventTime`（事情发生时间，`resolveTimeExpr` 把逐字表达式相对 mentionTime 确定性换算，支持中英：ISO 日期、"last/next week"、星期X、"N days ago"、"the week before 9 June 2023"、季节、"昨天/上周三/三个月前/去年"等）+ `mentionTime`（何时被提及）。"10 月聊到的 9 月的挫折"这类查询两个锚都能命中。精度与表达式粒度一致（"去年"=year 精度，不会误当成某个具体日期）。

## 2. 多实体、重复事件与别名：关联与去重

### 2.1 实体消解（三级，宁分裂勿错并）

同一概念多次出现必须合并为一个节点，否则图碎成孤岛（run-2 实测 45.8% 节点是重复）：

1. **规范化名精确匹配（类型无关）**：`lowercase(collapse-space(trim(n)))`，规范名+全部别名建哈希索引。**不按类型过滤**——抽取模型对同一名字的类型判定逐轮翻转（PERSON↔CONCEPT），类型过滤是碎裂的唯一来源；先建者的类型保留；
2. **嵌入近似合并**（同步 embedder 档）：cos ≥ 0.9 才并——"雪球/My cat 雪球"可靠合并，"张伟/张薇"不误并；
3. **LLM 裁决合并**（exact-miss 的主/客体提及）：嵌入粗召回候选（cos ≥ 0.6 top-5；嵌入不可用时包含关系兜底）→ 一次 LLM 调用裁决，**必须显式答 `sure` 才合并**（实测裸 yes 会把 "Islam"→"Iman"、"Shapur I"→"Ardashir I" 这类形似神不似的名字错并）；候选带类型与各自的一条已知事实（上下文才是判别证据，光看名字不够）；
4. **合并即别名累积**：新名字并入别名集、索引同步——之后任一叫法都命中同一节点。

### 2.2 事件去重

- **同轮幂等**：同 (session, turn, 谓词, 规范化事实, timeExpr) 只写一次——崩溃重抽不翻倍，同轮分段间的重复行不叠加；
- **注入近重复行抑制**：token 集 Jaccard ≥ 0.85 的同文事件在注入块里只占一席（跨轮重复抽取的变体不再浪费演位）。

### 2.3 冲突事实的 supersede（更新，不是简单重复）

用户先说"住杭州"后说"搬到上海"——新旧都留（历史完整、可审计、可答"之前住哪"），但呈现要有新旧秩序：

1. **撞车检测**：同主体实体 + 同关系。谓词写法会漂移（`has_headquarters_in`/`headquarters_in`/`has headquarters in city`），所以同关系的判定是**掩码客体值后的事实文本 Jaccard ≥ 0.8**（谓词相同直接算）——与谓词写法彻底解耦；
2. **LLM 裁决关系基数**："这个关系是单值（住所/职位/首都，新值取代旧值）还是多值（爱好/语言/子女，新值并列）"——模型裁决的是语义属性（它能答），时序由**插入序**提供（同轮到达的冲突事实 mentionTime 相同，曾整组漏裁）；
3. **防线**：重提守卫（客体值已存在的新事件是旧信息重提，不进裁决——提及顺序≠信息新旧）+ 标记传播（旧值的重提继承 supersede 标记）+ 多值先验（≥3 个不同值直接按多值，不花裁决调用）；
4. **呈现**：旧值打 `supersededBy` 链接 → 现在时检索 ×0.3 降权，历史区间查询全分可见；top-k 内冲突组**新值居首**；旧值带 `[superseded — newer value exists]` 标记。

## 3. 记忆注入：检索与打分

### 3.1 入口与查询构造

- **被动注入**：每轮第一步（`agent/pre-step` waterfall），取当前用户消息 → `distillQuery` 提取检索词（标点启发式主路：长消息取最后一个含 `?`/`？` 的行并剥离 `标签：` 前缀——确定性代码不会被任务型文本带偏；LLM 逐字引用蒸馏兜底：仅覆盖无问句标点的长消息，prompt 明示"引用原问题，不要回答"，磁盘缓存，失败透传）。>4000 字符的用户消息视为文档粘贴，跳过注入。
- **主动回忆**：`memory_search` 工具，模型自造查询；返回结果附带 top-3 命中实体的最新邻接事实（`via <实体>` 标记）——多跳问题"搜一跳、沿 via 实体搜下一跳"，不用先猜中间实体名。

### 3.2 候选生成

三个来源的并集：

1. **实体锚定**：查询中逐字出现的已知实体名/别名 → 这些实体的全部事件；
2. **稠密 top 切片**：全图按 cos(查询向量, 事件向量) 取前 2k（本地 ONNX 多语言嵌入 distiluse-base-multilingual-cased-v2 512 维；嵌入不可用退化为 IDF 词重叠切片）；
3. **一跳图扩展**：dense 切片前 15 条涉及的实体，其邻接事件（每实体至多 200 条）并入候选。

### 3.3 打分公式（完整）

$$\text{score}(v) = \delta_{\text{speech}}(v)\cdot\delta_{\text{superseded}}(v)\cdot\Big[\cos(\mathbf{v}_q, \mathbf{v}_v) + 2\cdot\frac{\sum_{w \in q^\*}\text{idf}(w)\,[w \in W_v]}{\sum_{w \in q^+}\text{idf}(w)} + \min\!\big(0.25\!\!\sum_{w \in q^+ \setminus q^\*}\!\!\text{idf}(w)\,[w \in W_v],\ 2\big) + 0.5\!\!\sum_{d \in D}\!\text{idf}(d)\,[d \in W_v] + 0.5\cdot[V(v) \cap E_q \neq \emptyset] + b_T(v, \text{op})\Big]$$

逐项含义：

| 项 | 含义 | 量级 |
|---|---|---|
| $\cos(\mathbf{v}_q, \mathbf{v}_v)$ | 稠密语义相似（查询/事件文本向量，事件文本 = 实体名+谓词+事实+细节） | 0~1 |
| $2 \times$ IDF 归一化词重叠 | $q^*$ = 查询词干集（轻量词干化 + 停用词 + CJK bigram）；$\text{idf}(w) = \ln\frac{N+1}{\text{df}(w)+1} + 1$ 在候选池内动态计算 | 0~2 |
| 扩展词奖励 | $q^+ = q^* \cup$ LLM 扩展词（≤12 个，含纠错与同义词，磁盘缓存）；命中扩展词的 IDF 加权，封顶 2 | 0~2 |
| 关键描述词 | $D$ = 剥离疑问脚手架（what/how/kind of）与通用轻动词（make/take/like…）后的实义词干，每个命中 0.5·idf | 无封顶但词少 |
| 实体奖励 | 事件涉及查询中提到的已知实体 +0.5 | 0/0.5 |
| $b_T$ 时间奖励 | 见下方时间算子表 | 0~0.3 |
| $\delta_{\text{speech}}$ | 言语行为事件（KIND=speech）×0.3——"User asked …"与后来的问题逐字重合，不打折会霸榜 | 0.3/1 |
| $\delta_{\text{superseded}}$ | 被取代事件在现在时模式 ×0.3（历史区间查询不打折） | 0.3/1 |

**时间算子**（查询先被解析成算子，再决定过滤与奖励）：

| 算子 | 触发 | 行为 |
|---|---|---|
| `DENSE` | 无时间意图 | 不过滤；仅提及新近度小奖励 $0.3/(1+d_m/30)$ |
| `LAST_K` | "最近一次"、"the last time" | 不硬过滤；$0.25/(1+d/14)$（事件时间优先，缺失用提及时间） |
| `WITHIN_WINDOW` | "最近"（180 天）、"in the past 3 weeks"、"昨天" | 硬过滤窗口外事件；奖励 $\max(\frac{0.2}{1+d_e/14}, \frac{0.1}{1+d_m/14})$ |
| `RANGE` | "上周/本周/上个月/本月"、"last/this week/month" | **日历区间** [start, end) 硬过滤（不是粗滚动窗口——周五问"上周"时上周一距滚动窗 11 天）；双锚命中 |
| `IN_YEAR/MONTH/SEASON` | "last year"、"in June 2025"、"during the summer"、"去年" | 日历区间硬过滤 |

**双锚规则**：范围匹配 = $t_e$ 或 $t_m$ 任一落入区间即命中；$t_e$ 命中的排序权重高于 $t_m$（"9 月发生的事"应排在"9 月随口提到的事"之前）。

**对话局部性加成**（打分后）：top-5 锚点事件的同轮/±1/±2 轮事件获有界加成（分项封顶、随锚点得分缩放），共享客体实体再加 min(1.8, 0.25×锚点分)——"聊到某件事时，它前后文的事也相关"。

**排序与呈现**：(score 0.25 分桶, 查询覆盖率, 命中 IDF 质量) 三级 tie-break；**状态族去重**（goal_/todo_/schedule_/plan_ 桥事件每实体每族只留最新）；**冲突组新值居首**；列表类问题追加 MMR 多样性重排（$\text{score} - 3.0 \cdot \max\cos(\cdot, \text{已选})$，防近重复挤占席位）。最终 top-k（默认 8）渲染为 `- [时间] 事实 (细节) [superseded 标记]`，总量 ≤2000 字符，以 plugin 来源的 user/message 注入并落盘进会话日志（模型可见 ⟺ 审计可见）。

## 4. 效果证据

- **功劳归属**（同一骨架 deepseek-v4-flash 贯穿，工具白名单审计排除作弊）：run-2 全量 1027 题条件答对率——注入召回时 **88.6%**、搜到时 67.0%、**从未召回仅 20.3%**。答对几乎完全由召回决定。
- **注入召回率**：run-2 的 7.7% → mini-7 的 50%+（SH 档 80-100%）。
- **实体健康**：重名组 2820 → 各轮新图均为 0。
- **时间轴**：固定中文剧本探针 6/6（双锚、日历周、冲突取新值、跨语言实体合并）。
- **LME judge（子集）**：60% → 80%，temporal-reasoning 2/2。
- **逐轮对照与残留问题**：附录 A。
